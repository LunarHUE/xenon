<Section title="as">

Components render a default element. Most parts take an `as` prop to render a
different element or one of your own components, and the behavior moves with
it.

Button reads `as` to pick its semantics. `a` with an `href` stays a native link
and `input` a native input. Any other host gets `role="button"`, a tab stop,
and Enter and Space activation.

```tsx title="link-button.tsx"
<Button as="a" href="/settings">
  Account settings
</Button>
```

A part can render another xenon component. Here the trigger hands its props and
ref to Button, so the tooltip opens from a native button.

```tsx title="tooltip-trigger.tsx"
<Tooltip>
  <Tooltip.Trigger as={Button}>Save</Tooltip.Trigger>
  <Tooltip.Portal>
    <Tooltip.Positioner>
      <Tooltip.Content>Saves a draft</Tooltip.Content>
    </Tooltip.Positioner>
  </Tooltip.Portal>
</Tooltip>
```

</Section>

<Section title="ref">

`ref` preserves the selected host's Solid type. Callback refs receive the rendered
element, and nested callback arrays let multiple consumers share it. Xenon attaches
its internal ref before forwarding to consumers.

```tsx title="editor.tsx"
function Editor() {
  let save: HTMLButtonElement | undefined
  const onKeyDown = (event: KeyboardEvent) => {
    if (event.key === 'Escape') save?.focus()
  }

  return (
    <>
      <textarea onKeyDown={onKeyDown} />
      <Button ref={(el) => (save = el)}>Save</Button>
    </>
  )
}
```

A component passed to `as` must forward the props and the ref it receives to
the element that gets the behavior. Spreading `props` onto that element does
both.

In development Button logs an error if the ref never arrives. It also logs one
if your component renders a native button, input or link, since that element
would get `role="button"` instead of its native semantics. Pass the tag as `as`
instead.

```tsx title="card.tsx"
import type { ComponentProps } from '@solidjs/web'

function Card(props: ComponentProps<'div'>) {
  return <div {...props} />
}

function Project() {
  return <Button as={Card}>Open project</Button>
}
```

</Section>

<Section title="Native props">

Host props retain Solid's native types wherever component behavior does not own
them. `class` accepts Solid's native class values; the styled layer merges those
values with its recipe. The headless adapter does not add `classList` compatibility.

Native boolean attributes consumed by behavior, such as `disabled` and
`autofocus`, accept `true`, `false`, and `""`. The empty value enables the flag.
Behavior-only options such as `pending` remain booleans.

Consumer event handlers run before matching Xenon handlers. Functions and Solid's
`[handler, data]` tuples are supported. An undefined consumer handler leaves Xenon's
behavior intact; calling `preventDefault()` skips the matching Xenon handler.

Ordinary forwarded attributes support removal through explicit undefined values.
Some props, such as generated control IDs and controlled state, belong to the
component's behavior and have their own documented defaults.

</Section>
