<Section title="Headless">

Each component handles behavior, keyboard interaction and ARIA wiring. None of
them ship CSS. You write the markup and the styles, and the component attaches
roles, attributes and event handlers to the elements it renders.

</Section>

<Section title="Styling">

`class` and `style` pass through to the element each part renders, and state
shows up as data attributes like `data-disabled`. The
[Styling guide](/docs/styling/) covers the attributes, focus styles and CSS
variables.

</Section>

<Section title="Packages">

Applications install `@xenon-ui/solid`. The behavior behind it lives in
`@xenon-ui/core`, which is plain TypeScript with no framework and no DOM. Each
core component is a function that takes options and returns state plus
attribute and listener maps for its parts. You only need core directly to write
an adapter for another framework.

</Section>

<Section title="Components">

Accordion, AlertDialog, Avatar, Breadcrumbs, Button, Calendar, Checkbox,
CheckboxGroup, Collapsible, Combobox, ContextMenu, Dialog, Drawer, Editable,
Field, HoverCard, Listbox, Menu, Menubar, Meter, NavigationMenu, NumberField,
Pagination, PinInput, Popover, Progress, RadioGroup, RangeCalendar, Resizable,
ScrollArea, Select, Separator, Slider, Switch, Tabs, TagsInput, Toast, Toggle,
ToggleGroup, Toolbar, Tooltip, plus AccessibleIcon and VisuallyHidden.

These docs cover Button so far. This is a pre-release, and APIs can still move
before 1.0.

</Section>
