# presence

The mount/unmount and enter/exit animation contract. Every overlay (dialog,
popover, tooltip, menu, select, toast, drawer, hover card, navigation menu) and
every disclosure (collapsible, accordion, tabs panel) delegates its "when may
this element actually leave the DOM" question here, so this file is the shared
dependency behind all of them. The APG says nothing about any of it: there are
no `[apg]` bullets below, which is exactly why the libraries disagree so widely.

## presence

### Roles and attributes

- [ ] `presence.roles.1` Given a presence-controlled element, then the presence layer sets no role and no ARIA attribute of its own: it decides mount state and stamps state attributes, and the consuming component supplies the semantics. [radix, base-ui, zag, ark, reka, corvu]
- [ ] `presence.roles.2` Divergence: given a presence-controlled element, then open state is exposed as `data-state="open"` while present and `data-state="closed"` while not. [radix, base-ui, zag, ark, reka, melt, bits] (decision needed)
- [ ] `presence.roles.3` Divergence: given a presence-controlled element, then open state is exposed as `data-expanded` / `data-collapsed`, with the absent state omitting the attribute rather than writing `"false"`. [corvu] (decision needed)
- [ ] `presence.roles.4` Divergence: given a presence-controlled element, then the transition phase is exposed as `data-starting-style` while entering and `data-ending-style` while leaving, and no attribute at all while idle. [base-ui, bits] (decision needed)
- [ ] `presence.roles.5` Divergence: given a presence-controlled element, then the transition phase is exposed as `data-enter` while shown, `data-leave` while leaving, and `data-animating` for the whole duration of either, removed once the transition ends. [ariakit] (decision needed)
- [ ] `presence.roles.6` Given the phase-to-attribute mapping, then `'starting'` yields `{ 'data-starting-style': '' }`, `'ending'` yields `{ 'data-ending-style': '' }`, and `'idle'` or `undefined` yields nothing, with the attribute names pinned against literals so a rename cannot slip through. [base-ui]
- [ ] `presence.roles.7` Given a mounted but not-present element, then it carries the native `hidden` attribute. [zag, ark, reka, bits, base-ui]
- [ ] `presence.roles.8` Given a force-mounted element, then the render function receives the current presence so the consumer can reflect it, for example as `data-present="true"` / `"false"`. [reka] (candidate)
- [ ] `presence.roles.9` Given an element opened without motion for a reason the consumer may want to style (a zero-delay tooltip, a focus-opened tooltip, a click-opened menu), then it carries `data-instant="<reason>"` while that applies and loses the attribute afterwards; the attribute is a styling hint only and does not skip the entering phase. [base-ui] (candidate) (browser-only)
- [ ] `presence.roles.10` Given a dedicated presence component, then it additionally stamps `data-scope="presence"` and `data-part="root"` on the rendered element. [ark] (candidate)

### Focus management

- [ ] `presence.focus.1` Given an element still mounted in its ending phase, then focus management skips it: tabbing into a container lands on a surviving sibling, and closing the focused item moves focus past every item that is animating out. [base-ui] (candidate)

### State

- [ ] `presence.state.1` Divergence: given a presence machine, then it exposes a two-valued mount decision only: the element is rendered or it is not, with the in-between kept internal. [radix, reka] (decision needed)
- [ ] `presence.state.2` Divergence: given a presence machine, then it exposes three states, `present`, `hiding` and `hidden`, with a single `present()` accessor that is true for both `present` and `hiding`, so callers keep the element mounted for both. [corvu] (decision needed)
- [ ] `presence.state.3` Divergence: given a presence machine, then it exposes three states, `mounted`, `unmountSuspended` and `unmounted`, with `present` true in the first two, plus `setNode(node)` to register the animated element and `unmount()` to force the unmounted state. [zag, ark] (decision needed)
- [ ] `presence.state.4` Divergence: given a presence machine, then it exposes a transition status of `'starting' | 'ending' | 'idle' | undefined` alongside the boolean open state, so the phase is a separate axis from mount state. [base-ui] (decision needed)
- [ ] `presence.state.5` Given the shown flag flips to true, then the element becomes present immediately with no intermediate suspended step: entering is never deferred. [corvu, zag, radix]
- [ ] `presence.state.6` Given the very first presence change, then it is reported as skippable so the initial render can be committed without an enter animation; the flag flips on a microtask so the first change and every later one are distinguishable. [zag, ark]
- [ ] `presence.state.7` Given an element present on first render, then the enter tracker is skipped entirely and the enter-completion callback does not fire for the initial mount. [zag, base-ui]
- [ ] `presence.state.8` Given a completion callback, then it fires once the enter or exit animation has actually finished, with no animation meaning it fires immediately; a closed element rendered with only that callback never calls it on mount. [base-ui, zag, ark, corvu]
- [ ] `presence.state.9` Given the exit completes, then a non-bubbling completion event is also dispatched on the registered node, so a consumer can listen rather than pass a callback. [zag] (candidate)
- [ ] `presence.state.10` Given the completion callback fires for both directions through one function, then it receives the resulting open state, so "opened fully" and "closed fully" are the same callback with a different argument. [base-ui]
- [ ] `presence.state.11` Given a presence state change of any kind, then a state-change callback fires with the new state; the intermediate hiding state is not surfaced to the higher-level present/absent callback. [corvu] (candidate)
- [ ] `presence.state.12` Given the imperative unmount is called while present or suspended, then the machine goes straight to unmounted, clears the recorded animation name and runs the exit-completion path. [zag] (candidate)
- [ ] `presence.state.13` Given the same element is registered twice, then the second registration returns early; registering a different element replaces both the node reference and the cached computed style, and machine teardown clears both. [zag] (candidate)

### Animation and presence

- [ ] `presence.animation.1` Given an element with no exit animation, when it stops being present, then it is removed from the DOM immediately. [radix, base-ui, zag, ark, reka, corvu, ariakit]
- [ ] `presence.animation.2` Given an element toggled away and back before it has left, then it ends up mounted and is still the same DOM element. [radix, base-ui]
- [ ] `presence.animation.3` Divergence: given exit timing, then it is decided from CSS animations: `animationstart` records the current computed `animationName`, the exit suspends while that name is present, and `animationend` or `animationcancel` on the element itself releases it. [corvu, zag, ark, reka, radix] (decision needed)
- [ ] `presence.animation.4` Divergence: given exit timing, then it is decided from CSS transitions: the computed `transitionDuration` gates whether to wait at all and `transitionend` on the element releases the exit. [corvu, base-ui] (decision needed)
- [ ] `presence.animation.5` Divergence: given exit timing, then it is decided from the Web Animations API: `getAnimations()` is polled for unfinished animations and their `finished` promises drive completion, which covers transitions and keyframe animations with one mechanism. [base-ui] (decision needed)
- [ ] `presence.animation.6` Divergence: given exit timing, then it is decided from an explicit numeric timeout: the element stays mounted with its leaving attribute until the timeout elapses. [ariakit] (decision needed)
- [ ] `presence.animation.7` Given the exit is suspended, then the element stays mounted for the whole exit and is only removed afterwards, so an exit animation is always allowed to finish. [radix, base-ui, zag, ark, corvu, reka, bits, ariakit]
- [ ] `presence.animation.8` Given the resolved exit animation name is `none`, equals the name recorded at the last animation start, the element's computed `display` is `none`, or its `animationDuration` is `0s`, then the exit is not suspended and the element unmounts immediately. [zag, corvu]
- [ ] `presence.animation.9` Given an animation duration is set but `animation-name` is `none`, then it counts as no animation and the element unmounts immediately. [ariakit, zag]
- [ ] `presence.animation.10` Given several transitioning properties with different delays and durations, then the exit completes at the longest per-property end time rather than at `max(delay) + max(duration)`. [ariakit] (candidate) (browser-only)
- [ ] `presence.animation.11` Given an element whose box is already zero-sized, then it unmounts within one animation frame rather than waiting for an unrelated long transition. [base-ui] (candidate) (browser-only)
- [ ] `presence.animation.12` Given the shown flag flips to false while the owner document's `visibilityState` is `hidden`, then the element unmounts immediately and never waits for an animation. [zag] (candidate)
- [ ] `presence.animation.13` Given an animation event whose target is a descendant rather than the tracked element, then it is ignored, and the computed style is not even read for it. [corvu, zag, reka, radix]
- [ ] `presence.animation.14` Given a computed `animationName` listing several comma-separated animations, then an `animationend` matches when its own name is contained in that list rather than by strict equality. [corvu]
- [ ] `presence.animation.15` Given the exit is suspended, then `animation-fill-mode: forwards` is applied to the node for the duration and the previous inline value is restored on cleanup, so the element holds its final frame instead of snapping back. [zag] (candidate)
- [ ] `presence.animation.16` Given an animation that is canceled mid-flight, then presence still resolves: the exit completes rather than leaking a permanently mounted element, and if `getAnimations()` returns a replacement animation the wait continues until that replacement finishes instead. [corvu, base-ui]
- [ ] `presence.animation.17` Given a running animation whose keyframes are swapped mid-flight so the animation restarts, then completion waits for the restarted animation and fires exactly once. [base-ui] (candidate) (browser-only)
- [ ] `presence.animation.18` Given an element dismissed during its enter animation, then the open-completion callback never fires and the close-completion callback fires exactly once. [base-ui] (candidate) (browser-only)
- [ ] `presence.animation.19` Given a close interrupted by a reopen, then a stale close animation finishing afterwards does not restart the entrance and does not reapply the starting-style attribute, and a subsequent close still reaches the ending phase on the same element. [base-ui] (candidate) (browser-only)
- [ ] `presence.animation.20` Given an element that is present on first render, then its mount animation is suppressed once: the computed `animation-name` is `none` for that first paint and normal animation resumes on the next state change. [base-ui, corvu, zag]
- [ ] `presence.animation.21` Divergence: given force-mount, then it is spelled `forceMount` and keeps the element rendered regardless of state. [radix, reka, bits, corvu] (decision needed)
- [ ] `presence.animation.22` Divergence: given force-mount, then it is spelled `keepMounted` and applies per part, with a root-level value inherited by the parts unless a part overrides it. [base-ui] (decision needed)
- [ ] `presence.animation.23` Divergence: given force-mount, then it is spelled `static` on the content part and the render strategy can be swapped separately. [headlessui] (decision needed)
- [ ] `presence.animation.24` Divergence: given force-mount, then it is two orthogonal flags: `lazyMount` suppresses the first mount only and `unmountOnExit` removes the element only after a full presence cycle, so their four combinations are four distinct behaviors. [zag, ark] (decision needed)
- [ ] `presence.animation.25` Divergence: given force-mount, then it is spelled `unmountOnHide: false`, the inverse of the default. [reka, ariakit] (decision needed)
- [ ] `presence.animation.26` Given a render-function child, then it force-mounts by definition: the function is always called and receives the presence state, so the consumer decides whether to render anything at all. [radix, reka, bits]
- [ ] `presence.animation.27` Given a render function that returns nothing as soon as the element stops being present, then the exit still completes and the state machine does not wedge; given one that only mounts its host element once the exit has begun, then the ending phase is observed and the element still ends up removed. [base-ui] (candidate)
- [ ] `presence.animation.28` Divergence: given a mounted-but-hidden element under React 19, then wrapping it in `Activity mode="hidden"` pauses the effects inside it, whereas the `hidden`-attribute mode leaves them running; the Activity mode falls back to the attribute when the running React version does not provide it. [ark] (decision needed)
- [ ] `presence.animation.29` Given an element revealed again by React's `Activity` after it was already open, then it fires no `transitionrun` and runs no animations: revealing must not replay the enter animation, including when the keyframes came from inline styles. [base-ui] (browser-only)
- [ ] `presence.animation.30` Given both a CSS transition and a CSS keyframe animation on the same element, then a development warning says only one of the two should be used, because the two exit-timing mechanisms cannot both own the decision. [base-ui]
- [ ] `presence.animation.31` Given a size-transitioning element, then the measured size is published as a CSS custom property and the animation is left entirely to CSS rather than driven by an inline `height`. [corvu, base-ui, zag, kobalte, radix]
- [ ] `presence.animation.32` Given a size must be measured while an animation is declared, then the implementation temporarily forces `animation-name: none` (and `transition-duration: 0s`), reads the offset size, and restores both, so the measurement is not distorted by a running animation. [corvu, kobalte]
- [ ] `presence.animation.33` Given an intrinsically sized element that must transition between two content sizes, then the recipe is: record the old size on the first resize callback without animating, pin the element at the old size in one batch, release it to the new size after two animation frames, and reset on `transitionend`; a computed `transitionDuration` of zero resets immediately instead of waiting for a `transitionend` that never arrives, and further resize callbacks during the transition are ignored rather than chained. [corvu] (candidate)
- [ ] `presence.animation.34` Given enter and exit style sets plus a set of common styles, then the composed style object contains the phase's own values, the common values, a `transition-property` that is the deduplicated union of the enter and exit property names in insertion order, and the duration with its unit appended; a common style is applied in both phases without appearing in `transition-property`. [kobalte]
- [ ] `presence.animation.35` Given transition classes for the enter and leave phases (`enter`, `enterFrom`, `enterTo`, `leave`, `leaveFrom`, `leaveTo`), then they are applied to the element at the right frames, multi-line class lists are supported, and an `appear` flag applies the enter classes immediately on mount. [headlessui] (candidate)
- [ ] `presence.animation.36` Given nested presence-controlled elements where children are still transitioning, then the parent does not unmount the tree until the children have finished. [headlessui] (candidate)
- [ ] `presence.animation.37` Given completion callbacks that opt into batching, then callbacks finishing in the same microtask coalesce into a single commit, an abort signal fired mid-flush skips the remaining callback, and the default non-batched mode commits each callback separately so a later callback observes the earlier one's state update. [base-ui] (candidate)

### RTL and i18n

- [ ] `presence.rtl.1` Given the presence layer, then it is direction-agnostic: no bullet in any library's presence primitive reads `dir` or a locale. Direction only reaches the CSS that the consumer writes. [radix, base-ui, zag, ark, corvu, reka]

### SSR and hydration

- [ ] `presence.ssr.1` Given server rendering, then the presence layer does no work: it measures nothing, attaches no observer and reports the not-yet-measured size as zero or null, because all of it runs in an effect. [corvu, base-ui]
- [ ] `presence.ssr.2` Given an element rendered present on the server whose enter animation comes from a CSS rule or from inline styles, then the emitted markup carries `animation-name: none` while the duration is preserved, so the enter animation does not play on first paint. [base-ui]
- [ ] `presence.ssr.3` Given server rendering without an explicit appear flag, then no transition classes are inserted into the markup, and a fragment-rendered child keeps its own `className`. [headlessui] (candidate)
- [ ] `presence.ssr.4` Given a mounted-but-hidden element using `display: none` rather than removal, then the closed content is present in the server-rendered HTML so crawlers can read it. This is the documented reason that hide mode exists. [corvu]

### Accessibility tooling

- [ ] `presence.a11y.1` Given an element mounted while not present, then hiding it with `aria-hidden="true"` makes any focusable descendant an axe `aria-hidden-focus` violation at serious impact; `hidden`, `inert` or removal avoids it, and axe's own `isFocusable` already treats inert content as not focusable. [axe]
- [ ] `presence.a11y.2` Given a presence-controlled element in the not-present state, then an axe run over the container reports no violations. [axe, ark]
- [ ] `presence.a11y.3` Given an element in its ending phase, then it must already be inaccessible to assistive technology even though it is still in the DOM, so a screen reader does not announce something that is visually leaving. [base-ui]

### Notes and edge cases

- [ ] `presence.notes.1` Given jsdom, then `getComputedStyle(element).animationName` returns the empty string rather than `"none"`. The Solid presence primitive tests `currentAnimationName === 'none'`, so the fast path never fires: the code falls through to comparing the recorded previous name (initialized to `"none"`) against `""`, the two differ, and the element enters the `hiding` state waiting for an `animationend` that jsdom will never dispatch. That single falsy-versus-`"none"` mismatch is why every negative presence assertion in Kobalte's accordion, collapsible, checkbox and toast suites is commented out with `// TODO: fix solid-presence vitest`. Fix it by treating an empty animation name as `none`, by dispatching a synthetic `animationend`, or by stubbing `getComputedStyle`. [corvu, kobalte]
- [ ] `presence.notes.2` Given the same primitive, then the dependency is structural rather than incidental: Kobalte imports corvu's `solid-presence` in fourteen source files (checkbox indicator, radio item indicator, collapsible content, tabs content, dialog, popover, select, combobox, menu, navigation menu, tooltip, hover card, toast), so fixing its jsdom behavior unblocks assertions across a dozen components at once. [kobalte, corvu]
- [ ] `presence.notes.3` Given a collapsible content element, then the component itself writes and clears inline `animation-name` and `transition-duration` mid-transition in order to measure the content at full size, which is the same inline `animation-name` the presence primitive reads. The timing is genuinely subtle rather than only a jsdom artifact, which is likely why those assertions were commented out instead of patched. [kobalte]
- [ ] `presence.notes.4` Given Base UI's shared popup conformance harness, then its `animations > removes the popup when the animation finishes` test is currently disabled: the body calls `skip()` unconditionally with the comment "XXX: revisit after feedback from the team". Had it run it would inject a `@keyframes` animation bound to `[data-ending-style]`, keep the portal mounted, close the popup, and assert the popup becomes inaccessible while still mounted and that `onAnimationEnd` fires exactly once. That is the single highest-value gap for this suite to close, because it is the only generic assertion of the exit contract in either library. [base-ui]
- [ ] `presence.notes.5` Given `prefers-reduced-motion: reduce`, then no library in the research derives presence timing from it: the one place it is tested at all is Ariakit asserting that a dialog and its backdrop run no animation, and that a popover runs none, under reduced motion. Kobalte ships a `matchMedia` mock for exactly this query and never calls it. So reduced-motion handling is entirely a CSS-author responsibility today, and if the presence layer is to honor it the behavior has to be designed rather than copied. [ariakit, kobalte] (candidate) (browser-only)
- [ ] `presence.notes.6` Given a library that offers both an animation-based and a transition-based exit mechanism, then a component must pick one and the two cannot be mixed: corvu's presence primitive keys on animations while its drawer keys on `transitionDuration` and `transitionend`, so the two live side by side with no shared timing. [corvu]
- [ ] `presence.notes.7` Given the recorded animation name, then it is kept in a plain non-reactive variable so an `animationstart` does not schedule an update, and the presence effect threads the previous shown value through the effect's return value. Both patterns are load-bearing and both need equivalents to port. [corvu]
- [ ] `presence.notes.8` Given an element removed from the DOM whose state should survive re-insertion, then a companion primitive caches the rendered output together with a shallow copy of its owner and re-runs it with that owner. Copying an owner object is deep framework-internals territory and deserves a dedicated test: mount, unmount, remount, assert the internal state survived. [corvu]
- [ ] `presence.notes.9` Given a presence-controlled element whose child ref is unstable (a new callback identity each render that itself triggers a render on attach), then rendering does not loop: the commit count stays bounded and the real node still reaches the child's ref. [radix]
- [ ] `presence.notes.10` Given a resize-driven size read, then it is deferred to the next animation frame and rapid observations coalesce: earlier scheduled frames are canceled, only the final size lands, and a pending frame is canceled on unmount so no state update happens on an unmounted component. [radix]
- [ ] `presence.notes.11` Given jsdom, then `offsetWidth` and `offsetHeight` are always `0`, `ResizeObserver` is undefined, and `getComputedStyle(...).transitionDuration` is the empty string (so `parseFloat` yields `NaN` and a zero-duration fast path never fires). Any size or transition assertion needs the offset getters redefined, a `ResizeObserver` stub whose callback can be triggered with a fabricated entry, and a hand-dispatched `transitionend`. [corvu, kobalte] (browser-only)
- [ ] `presence.notes.12` Given a double `requestAnimationFrame` deferral, then a test must flush two frames before the released size is observable; one microtask or one fake frame still reads the pinned old size. [corvu]
- [ ] `presence.notes.13` Given a presence-controlled element, then the polymorphic escape hatch applies here too: the presence attributes merge onto a consumer element instead of a default wrapper `div`. [ark, radix, base-ui]

## Deferred

- Which exit-timing mechanism to adopt (`presence.animation.3` through `presence.animation.6`) is the decision that everything else in this file hangs off. The Web Animations API option is the only one that covers transitions and keyframe animations with a single mechanism, but it is also the only one that needs `getAnimations()`, which jsdom does not implement, so choosing it makes every exit-timing test browser-only.
- Reduced motion has no cross-library contract to merge (`presence.notes.5`). It needs a design decision, not a merge.
- Base UI's `BASE_UI_ANIMATIONS_DISABLED` global, which its own tests flip off per test to enable real animations, is a test-harness concern for `packages/suite` rather than a component behavior. The equivalent switch for this suite has to exist before any animation bullet above can be tested at all.
- Kobalte's `createTransition` itself has no test file: only the pure style calculator is covered, and only for the `afterEnter` and `afterExit` phases. Mount and unmount timing, the element remaining present during exit, and every attribute or style applied while transitioning are uncovered there, and its phase map carries a commented-out value (`beforeExit` mapping to the entered styles with the original `"out"` left inline) that no test pins.
- Corvu's `dimension: 'both'` guard requires both axes to change with `&&`, which silently skips single-axis resizes and is almost certainly meant to be `||`. Its `ResizeObserver` callback also destructures only the first entry with a non-null assertion, so a batched delivery drops entries and an empty batch throws. Both are bugs to fix rather than behaviors to replicate.
- Headless UI's frame-by-frame class-timeline tests (eight of them), its nested-transition test and its "fires events for all the stages" test are `xit`-disabled in React and only enabled in Vue, so the React evidence for `presence.animation.35` and `presence.animation.36` is snapshot-shaped and unverified.
- `data-instant` (`presence.roles.9`) is Base UI's alone and is entangled with tooltip and menu open-reason tracking. It stays a candidate until those component specs land.
