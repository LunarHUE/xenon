# select

The trigger-plus-listbox picker: a button that carries `role="combobox"`,
`aria-haspopup="listbox"` and the current value, a listbox popup, and a hidden
native control for form submission and autofill. This is APG's select-only
combobox; an editable text input with a popup is `combobox.md`, and the popup's
own option semantics are in `listbox.md`.

Note: kobalte's entire select suite is `describe.skip` upstream, so every bullet
tagged kobalte here is read out of an executable specification that has never
run in CI. Treat those tags as unverified.

## select

### Roles and attributes

- [ ] `select.roles-and-attributes.1` Given the element that displays the value and opens the popup, then it has `role="combobox"`, and `combobox` carries an implicit `aria-haspopup="listbox"` that implementations also write explicitly. [apg, react-aria, radix, base-ui, zag, ark, reka, kobalte, ariakit]
- [ ] `select.roles-and-attributes.2` Given a select-only combobox, then `role="combobox"` may sit on a `div` or `button` with `role="listbox"` on a `div` and `role="option"` on its children, and the value is the combobox's own text content rather than an input value. [apg, radix, base-ui, zag, reka]
- [ ] `select.roles-and-attributes.4` Given a hidden popup, then the trigger has `aria-expanded="false"`; while the popup is visible, `aria-expanded="true"`. `combobox` defaults to `false`. [apg, react-aria, radix, base-ui, zag, kobalte, reka]
- [ ] `select.roles-and-attributes.5` Given a combobox, then `aria-controls` refers to the popup element; it only needs to be set while the popup is visible, though referencing a hidden element is also valid. [apg]
- [ ] `select.roles-and-attributes.6` Divergence: given a closed select, then the trigger has no `aria-controls` attribute at all, and it appears with the listbox id on open and is removed again on close, so the reference never dangles. [react-aria, radix, base-ui, kobalte, reka] (decision needed)
- [ ] `select.roles-and-attributes.7` Divergence: given `role="combobox"`, then both `aria-expanded` and `aria-controls` are required attributes, so a closed select with no `aria-controls` fails at critical impact regardless of popup visibility. [axe] (decision needed)
- [ ] `select.roles-and-attributes.8` Given `aria-controls` on a trigger that also carries `aria-haspopup`, then an unresolvable reference is reported incomplete ("Unable to determine if aria-controls referenced ID exists on the page while using aria-haspopup"), so a lazily rendered popup needs review rather than failing outright. [axe]
- [ ] `select.roles-and-attributes.9` Given a select-only combobox, then every option carries an explicit `aria-selected` of `"true"` or `"false"`, never an absent attribute. [apg, kobalte, zag, reka, melt]
- [ ] `select.roles-and-attributes.39` Given `role="combobox"` in the axe role table, then it is a widget-type role whose role-specific allowed attributes are `aria-owns`, `aria-autocomplete`, `aria-readonly`, `aria-required`, `aria-activedescendant` and `aria-orientation`, its superclass is `select`, a name is required, and its children are not presentational. [axe]
- [ ] `select.roles-and-attributes.3` Given a trigger rendered as a native `button`, then it carries `type="button"` so it never submits the surrounding form. [zag, reka, melt, headlessui]
- [ ] `select.roles-and-attributes.10` Divergence: given an unselected option, then it carries neither `aria-selected` nor the selected data attribute. [bits] (decision needed)
- [ ] `select.roles-and-attributes.11` Divergence: given an unselected option, then it carries `aria-selected="false"` explicitly (base-ui and reka also mark selection separately with a data attribute that is absent when unselected). [reka, kobalte, zag, base-ui] (decision needed)
- [ ] `select.roles-and-attributes.12` Given a multiple select, then the listbox carries `aria-multiselectable="true"`. [react-aria, base-ui, kobalte, zag]
- [ ] `select.roles-and-attributes.13` Given a select whose popup element is itself the listbox, then the popup holds the `role="listbox"`, the id that `aria-controls` points at, and `aria-multiselectable`; when an inner list part is present, the list takes all three and the popup drops to `role="presentation"`, with `aria-controls` pointing at the list id. [base-ui, zag]
- [ ] `select.roles-and-attributes.15` Given a select with a visible label part, then the trigger's accessible name is the label plus the current value read together (`aria-labelledby` listing both the label element and the value element). react-aria orders it value-then-label, kobalte label-then-value. [react-aria, kobalte]
- [ ] `select.roles-and-attributes.16` Given a trigger with only `aria-label` and no label part, then it keeps that `aria-label` and gains a self-referencing `aria-labelledby` that folds its own name into the composite name, and the open listbox is then labelled by the trigger id. [react-aria, kobalte]
- [ ] `select.roles-and-attributes.17` Given a trigger with an author `aria-labelledby`, then the value element's id is appended to it and the open listbox is labelled by the author's id alone; with both `aria-label` and `aria-labelledby` the order is author id, trigger id, value id. [react-aria, kobalte]
- [ ] `select.roles-and-attributes.19` Given an open select with a visible label, then the listbox borrows the field's label through `aria-labelledby`. [react-aria, kobalte, zag]
- [ ] `select.roles-and-attributes.20` Given a description part, then it has an id and the trigger's `aria-describedby` points at it; an error message part is referenced the same way, and a field-level description id is appended to an author-supplied `aria-describedby` rather than replacing it. [react-aria, base-ui, kobalte]
- [ ] `select.roles-and-attributes.22` Given nothing selected, then the trigger and the value element both carry a placeholder marker (`data-placeholder`, `data-placeholder-shown`) and the value element renders the placeholder text; selecting a value removes it. [radix, base-ui, zag, reka, bits]
- [ ] `select.roles-and-attributes.24` Given an item with an empty-string value, then it is legal, renders as a normal option, and selecting it puts the select back into the placeholder state rather than showing the item's own text. [radix, bits]
- [ ] `select.roles-and-attributes.25` Given a required select, then the trigger carries `aria-required="true"`. [base-ui, zag]
- [ ] `select.roles-and-attributes.26` Given a read-only select, then the trigger carries `aria-readonly="true"` and a `data-readonly` marker, the listbox also reports `aria-readonly="true"`, and the trigger stays Tab-reachable (unlike disabled). [base-ui, zag]
- [ ] `select.roles-and-attributes.27` Given a disabled select, then the trigger carries the native `disabled` attribute plus `data-disabled` and `aria-disabled="true"`, is skipped by Tab, and ignores clicks; toggling the prop back adds and removes all of it. [base-ui, zag, ark, kobalte, ariakit, headlessui]
- [ ] `select.roles-and-attributes.28` Given a group inside the popup, then the group element has `role="group"` with `aria-labelledby` pointing at its label element's id, and the group label carries `role="presentation"` (zag) or `aria-hidden="true"` (base-ui) so it is not announced twice. [radix, base-ui, zag, reka, bits]
- [ ] `select.roles-and-attributes.30` Given an item indicator part, then it is `aria-hidden="true"`, carries a checked/unchecked state attribute, and is absent (or `hidden`) unless its item is selected. [radix, base-ui, zag, kobalte, reka, bits]
- [ ] `select.roles-and-attributes.31` Given the trigger's dropdown icon part, then it is `aria-hidden="true"`. [radix, zag]
- [ ] `select.roles-and-attributes.34` Given each item, then it carries a stable id derived from its value, a `data-value`, a checked/unchecked state attribute, a highlighted marker and, when disabled, both `data-disabled` and `aria-disabled`. [radix, base-ui, zag, kobalte, reka, bits]
- [ ] `select.roles-and-attributes.35` Given the trigger while open, then it also exposes the resolved popup placement (`data-placement`, `data-side`, `data-popup-side`) and a pressed marker, and the placement attribute is removed again on close. [base-ui, zag]
- [ ] `select.roles-and-attributes.14` Given a listbox popup, then it has no `aria-orientation` attribute, because a listbox is implicitly vertical. [base-ui] (candidate)
- [ ] `select.roles-and-attributes.18` Given a select with no label part at all, then the trigger has no `aria-labelledby` and no fallback id is invented. [base-ui] (candidate)
- [ ] `select.roles-and-attributes.21` Given a root id, then the trigger takes that id and a `label for` (native or field) resolves to it; changing the root id moves the trigger id, regenerates the label id and rewrites `aria-labelledby` in step. [base-ui] (candidate)
- [ ] `select.roles-and-attributes.23` Given a value that serializes to the empty string (including an object value whose serializer returns `""`), then the placeholder state still applies, so placeholder-ness is decided by the serialized string rather than by the value being non-null. [base-ui] (candidate)
- [ ] `select.roles-and-attributes.29` Given a group label that unmounts, then the group's `aria-labelledby` is removed; given a label swapped for another, the newer registration wins and an older label's cleanup cannot clear it. [base-ui] (candidate)
- [ ] `select.roles-and-attributes.32` Given a clear-trigger part, then it is a `button type="button"` with a translatable `aria-label` (default "Clear value") and is `hidden` whenever nothing is selected. [zag] (candidate)
- [ ] `select.roles-and-attributes.33` Given the popup viewport and scroll-button parts, then the viewport carries `role="presentation"` and the scroll buttons are `aria-hidden="true"`. [radix] (candidate)
- [ ] `select.roles-and-attributes.36` Given a select whose popup is open, then the outside content is swept with `aria-hidden`, so the trigger can no longer be found by an accessible-name query that ignores hidden nodes; any assertion about the trigger while the popup is open has to account for that. [kobalte] (candidate)
- [ ] `select.roles-and-attributes.37` Given a grid-shaped select popup, then the items are `gridcell`s rather than options. (candidate) [ariakit]
- [ ] `select.roles-and-attributes.38` Given a browser autofill on the hidden native control, then the trigger gains a `data-autofill` marker and its text follows the new value. (candidate) [ariakit]

- [ ] `select.keyboard.14` Given an open select, when Escape is pressed, then the popup closes and focus returns to the trigger, and an existing selection is kept rather than cleared. [apg, react-aria, kobalte, zag, melt, bits, reka]

- [ ] `select.keyboard.25` Given a select typeahead, when several different characters are typed, then the accumulated string narrows the match, and the buffer resets after a period of inactivity so the next keystroke starts a fresh search. [apg, react-aria, kobalte, zag]

- [ ] `select.keyboard.16` Divergence: given a loop flag, then the highlight wraps from the last option to the first and back; looping is opt-in in zag and bits and on by default in ariakit's `focusLoop`. [zag, bits, ariakit] (decision needed)

- [ ] `select.keyboard.19` Given an open select whose option list contains disabled items, when arrow keys move the highlight, then disabled options are skipped and a removed (null) item leaves no dead slot to land on. [react-aria, base-ui, kobalte, zag, reka]
- [ ] `select.keyboard.21` Divergence: given a closed, focused select, when characters are typed, then the matching option is committed as the value immediately without opening the popup, and the trigger text updates. [react-aria, kobalte, zag, base-ui] (decision needed)
- [ ] `select.keyboard.27` Given a select typeahead whose buffer has timed out, when a character that matches nothing on its own is typed, then nothing changes; a character that does match starts a fresh search and wraps around the collection from the current position. [react-aria, kobalte]
- [ ] `select.keyboard.32` Given a closed, focused select, when Left Arrow or Right Arrow is pressed, then the value steps to the previous or next option in collection order without opening the popup, mirroring the native `select`. [react-aria, kobalte, zag]

### Focus management

- [ ] `select.focus-management.1` Given a combobox receiving focus, then DOM focus is placed on the `combobox` element itself. [apg]
- [ ] `select.focus-management.15` Given an open select, then losing focus never steals focus back, and a blur whose `relatedTarget` is inside the widget's own popup is ignored. [apg, base-ui]
- [ ] `select.focus-management.21` Given an element with a negative `tabindex`, then the user agent considers it a focusable area but omits it from tabindex-ordered focus navigation, so `tabindex="-1"` is programmatically and click focusable but not Tab-reachable. [html]
- [ ] `select.focus-management.22` Given `tabindex="0"`, then the element is included in the sequential focus navigation order at its DOM position; positive values sort ahead of everything else and a headless library emits only 0 and -1. [html, axe]
- [ ] `select.focus-management.23` Given the focusing steps, then they return early when the target's DOM anchor is inert, no-op when it is already focused, and otherwise fire `blur` on the old chain and `focus` on the new chain with `relatedTarget` set. [html]
- [ ] `select.focus-management.24` Given `element.focus(options)`, then `preventScroll` defaults to false, so scrolling into view is the default and must be suppressed explicitly; `element.blur()` may do nothing at all, so a library never relies on it to move focus. [html]

- [ ] `select.accessibility-tooling.4` Given a combobox with a listbox popup, then every listbox-side rule applies to the popup: required children on the listbox, required parent on each option, accessible name on each option, and no nested interactive content inside an option. [axe]
- [ ] `select.accessibility-tooling.5` Given a select-only combobox built on a `div` with `tabindex="0"`, then `focus-order-semantics` passes because `combobox` is a widget-type role. [axe]
- [ ] `select.accessibility-tooling.6` Given a popup hidden with `aria-hidden="true"` rather than removed or `display: none`, then its focusable descendants must be made non-focusable or removed, at serious impact. [axe]
- [ ] `select.accessibility-tooling.7` Given a scrollable select popup, then it contains a focusable element or is focusable itself, at serious impact. [axe] (browser-only)
- [ ] `select.accessibility-tooling.8` Given an `autocomplete` attribute on the select's control, then its value must be correctly formatted; WCAG 2.1 AA 1.3.5 at serious impact. [axe]
- [ ] `select.accessibility-tooling.9` Given any element with a `role`, then the role is valid and non-abstract, every ARIA attribute on it is allowed for that role and host element, all required attributes are present, and every `aria-*` name and value is valid, at critical impact. [axe]
- [ ] `select.accessibility-tooling.10` Given an id referenced by `aria-controls`, `aria-labelledby`, `aria-describedby`, `aria-owns` or `aria-activedescendant`, then that id is unique in the document, at critical impact. [axe]
- [ ] `select.accessibility-tooling.1` Given a select with label, trigger, value text, indicator, clear trigger, portaled popup, groups, items and the hidden native control, when axe runs over it, then there are no violations; reka has to disable `aria-required-children` for the open state. [zag, ark, reka, melt]
- [ ] `select.accessibility-tooling.11` Given a trigger or option rendered with `aria-label` and no label element, then no `aria-labelledby` is invented for it. [ariakit] (candidate) (chrome-only)

### Notes and edge cases

- [ ] `select.notes-and-edge-cases.1` Given a choice between a select (combobox), a standalone listbox and a menu button, then combobox and menu button both let the user explore choices and back out with Escape, while navigating a single-select listbox changes its value immediately with no undo; a menu button cannot be marked required and has no value, so it must not convey a choice in its collapsed state. [apg]
- [ ] `select.notes-and-edge-cases.2` Given a select whose popup has no items, then it does not open at all. [react-aria, base-ui]
- [ ] `select.notes-and-edge-cases.8` Given any polymorphic select part, then unconsumed props, `className`, inline styles, refs and author event handlers all land on the rendered element, the author's handler composes with the library's rather than replacing it, and a swapped-in element keeps the part's role and state attributes. This holds for the trigger, icon, content or popup (in both positioning modes), viewport, group, group label, item, item text, item indicator, both scroll buttons, separator, arrow, positioner, portal, backdrop, value and the hidden input. [radix, base-ui]
- [ ] `select.notes-and-edge-cases.9` Given a select part rendered without its required ancestor, then the render fails with a message naming the missing context and the part that needs it. [base-ui, headlessui]
- [ ] `select.notes-and-edge-cases.3` Given an empty collection with an explicit empty-state renderer, then the popup opens with the listbox marked empty and one option carrying the empty-state content. [react-aria] (candidate)
- [ ] `select.notes-and-edge-cases.4` Given items rendered as links, then activating one navigates and commits no value: the popup closes, the trigger still shows the placeholder, and the click target is the anchor. [react-aria] (candidate)
- [ ] `select.notes-and-edge-cases.5` Given a router provider, then a relative item href is resolved through it and navigation is delegated with the item's router options. (candidate) [react-aria]
- [ ] `select.notes-and-edge-cases.6` Given a loading select, then a progressbar with no value is rendered (inside the trigger for the initial load, as a trailing option for loading more), the trigger's `aria-describedby` gains its id alongside any description, and both are removed when loading ends. (candidate) [react-aria]
- [ ] `select.notes-and-edge-cases.7` Given parts rendered inside the popup that also exist outside it (a label, a button, a description), then the select's contexts are cleared inside the popup so the inner label gets no `for`, the inner button no `aria-expanded` and the inner text no id. (candidate) [react-aria]
- [ ] `select.notes-and-edge-cases.10` Given the composed ref of the content, an item or an item text across re-renders, then it stays attached rather than being detached and reattached each render. [radix] (candidate)
- [ ] `select.notes-and-edge-cases.11` Given a root store that publishes several synchronized values, then a prop change lands as one transaction: no subscriber ever observes a snapshot mixing old and new values, `setOpen` is available to a descendant ref callback on the first commit, and an item ref callback sees the updated disabled state. [base-ui] (candidate)
- [ ] `select.notes-and-edge-cases.12` Given a select under a test runner, then opening by mouse needs a `pointerdown`, a flush, a `pointerup`, another flush and then a timer flush before the popup is queryable, and each key press is a separate keydown and keyup with its own flush; focus restore after close is gated on a `requestAnimationFrame`. [kobalte] (candidate)
- [ ] `select.notes-and-edge-cases.13` Given a select closed in a test, then asserting on a retained element's visibility sidesteps the unmount-timing problem that a "queried element is null" assertion runs into; kobalte's own suite is inconsistent about which it trusts. [kobalte] (candidate)
- [ ] `select.notes-and-edge-cases.14` Given a bits select opened in a test, then the test waits for the content node to appear in the global dismissable-layer registry before interacting, so the dismissal listeners are attached first. [bits] (candidate)
- [ ] `select.notes-and-edge-cases.15` Given a "controlled" select in a test, then driving the prop from a real signal is the only way to test that the component follows a prop change; a static prop only tests that it ignores its own intent. kobalte's suite does this exactly once. [kobalte] (candidate)

## Deferred

- Cascade select (a multi-column picker where each column's selection reveals the next). zag ships a whole machine for it with 84 research bullets: per-column `role="group"` lists carrying `data-depth` and `aria-level`, a single `role="listbox"` content with `aria-activedescendant` tracking the highlighted path, path-based values, and per-depth keyboard navigation. Only zag has it, and it needs its own spec file rather than a section here. [zag]
- Item-aligned (native macOS-style) popup positioning, and the scroll-arrow auto-scroll that goes with it. base-ui's coverage is large and almost entirely browser-mode: sub-pixel scroll math, growing the popup from the anchored edge as the list scrolls, zoom and pinch-zoom bail-outs, RTL inline-end alignment, and closing on window resize. The positioning bullets above are the shape of the contract; the geometry needs a browser harness. [base-ui, radix]
- The mobile tray: react-aria renders the options in a tray rather than a popover under a simulated mobile environment, and its test-utils Select tester has a tray mode. One library, and it needs a viewport harness. [react-aria]
- Virtualized select popups (Ariakit's `SelectRenderer` filtering and committing a rendered option). Shares a harness with `listbox.md`'s virtualization work. [ariakit]
- Grid-shaped select popups, where items are `gridcell`s and navigation is two-dimensional. Only Ariakit, and the APG's grid-popup rules belong with `combobox.md`. [ariakit, apg]
- Select composed with a combobox in the popup (a search field filtering the options). The behavior is specified in `combobox.md`; what is deferred here is the composition itself, including Ariakit's combined stores and its tabbed option lists. [ariakit, base-ui]
- Scroll locking and backdrop behavior under touch, which base-ui covers only in browser mode and which overlaps the dialog and popover specs. [base-ui]
