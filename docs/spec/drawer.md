## drawer

### Roles and attributes

- [ ] `drawer.roles.1` Given an open drawer with a title part and a description part, when the content is inspected, then it has `role="dialog"` (or `"alertdialog"` when asked for), `tabindex="-1"`, `aria-modal` reflecting the modal prop, `aria-labelledby` pointing at the title element and `aria-describedby` pointing at the description element, with each association present only when that part is rendered. [zag, reka]
- [ ] `drawer.roles.2` Given a closed drawer, when the trigger is inspected and then clicked, then it is a `type="button"` element with `aria-haspopup="dialog"`, `aria-controls` equal to the content element's id and `aria-expanded` tracking the open state. [base-ui, zag]
- [ ] `drawer.roles.3` Given a drawer that opens and closes, when the content, backdrop and trigger are inspected, then each carries an open or closed state attribute (`data-state="open"`/`"closed"` in zag, `data-open`/`data-closed` in base-ui and corvu) and the content and backdrop are hidden while closed. [base-ui, zag, corvu]
- [ ] `drawer.roles.4` Given a drawer configured for a side, when the content and backdrop are inspected, then both carry the resolved side as a data attribute, one of top, bottom, left or right in corvu and up, down, left or right in base-ui and zag, defaulting to the bottom edge. [base-ui, zag, corvu]
- [ ] `drawer.roles.5` Given a drag or swipe in flight, when the content, backdrop, swipe area and indent parts are inspected, then each carries `data-swiping`, and after release the attribute is gone; zag additionally sets `data-dragging` only while a drag offset exists. [base-ui, zag]
- [ ] `drawer.roles.6` Given a swipe that passes the dismiss threshold, when the pointer is released, then the element gains a swipe dismissal marker (`data-swipe-dismissed` in reka, `data-swipe-dismiss` in base-ui) so a swipe close can be styled apart from a click or Escape close, and a release below the threshold sets no such marker. [base-ui, reka]
- [ ] `drawer.roles.7` Given a provider with indent and indent background parts around two drawers, when the first drawer opens, then both parts carry `data-active=""` and drop `data-inactive`, they stay active while the second drawer is still open, and they return to `data-inactive=""` only once every open drawer is closed or removed. [base-ui, zag]
- [ ] `drawer.roles.8` Given an open drawer with a backdrop and an indent, when their inline styles are read, then the drawer publishes `--drawer-swipe-movement-x` and `--drawer-swipe-movement-y`, `--drawer-snap-point-offset`, `--drawer-swipe-progress`, `--drawer-height`, `--drawer-frontmost-height` and `--nested-drawers`, with the swipe progress being the absolute movement over the content size clamped to 0 through 1 and 0 at rest. [base-ui, zag, reka]
- [ ] `drawer.roles.9` Given a nested height metric of zero or a non-finite value, when the indent and backdrop styles are read, then `--drawer-height` and `--drawer-frontmost-height` are omitted or cleared to an empty string rather than written as `0px`, and a non-finite swipe progress reads as `0`. [base-ui, zag]
- [ ] `drawer.roles.10` Given a drawer whose content holds a nested drawer, when the nested drawer opens, then the parent content carries `data-nested-drawer-open=""` and `--nested-drawers: 1`, and a plain dialog or alert dialog opened inside the nested drawer never raises that count to 2. [base-ui, zag]
- [ ] `drawer.roles.11` Given a nested drawer being swiped, when the movement passes the gesture threshold, then the parent content gains `data-nested-drawer-swiping=""` with a non-zero `--drawer-swipe-progress`, and reversing the finger before release or releasing clears both. [base-ui, zag]
- [ ] `drawer.roles.12` Given a drawer at any translate value, when the content's inline transform is read, then it is a `translate3d` on the drawer's own axis whose sign follows the side, with the cross axis pinned to `0px` and the stored offset kept positive regardless of side. [zag, corvu]
- [ ] `drawer.roles.13` Given a drawer in a transition, when the content is inspected, then `data-transitioning` is present for the union of transitions and `data-opening`, `data-closing`, `data-snapping` or `data-resizing` discriminates the cause, with `data-resizing` appearing only when resize transitions are enabled. (candidate) [corvu]
- [ ] `drawer.roles.14` Given a drawer with an overlay, when the overlay is inspected, then it carries the same side and transition attributes as the content so the backdrop can be animated in lockstep from CSS alone. (candidate) [corvu]
- [ ] `drawer.roles.15` Given a rendered swipe area, when it is inspected, then it has `role="presentation"`, `aria-hidden="true"`, the resolved opening direction as a data attribute, `data-disabled=""` when disabled, `touch-action: pan-x` for a vertical opening direction or `pan-y` for a horizontal one, and `pointer-events: none` when disabled or when the drawer is open and not currently swiping open. (candidate) [zag]
- [ ] `drawer.roles.16` Given a rendered grabber, when its inline style is read, then `touch-action` is `none` so the browser does not scroll the page while the grabber is dragged. (candidate) [zag]
- [ ] `drawer.roles.17` Given a non-modal drawer, when the positioner and content are inspected, then the positioner has `pointer-events: none` while closing or when not modal and the content has `pointer-events: auto`, so the page behind stays interactive. (candidate) [zag]

### Keyboard

- [ ] `drawer.keyboard.1` Given an open drawer, when Escape is pressed, then the content is hidden, the title text leaves the document and focus returns to the trigger. [zag, reka]
- [ ] `drawer.keyboard.2` Given a drawer opened by swiping up from the swipe area, when Escape is pressed, then the content is hidden and the indent parts flip back to `data-inactive=""` with `--drawer-swipe-progress` at 0. (candidate) [zag]
- [ ] `drawer.keyboard.3` Given an open drawer whose content holds an input inside an outer keydown handler, when ArrowDown is pressed on the input, then the outer handler is not called, and when a printable key is pressed it is. (candidate) [base-ui]

### Pointer

- [ ] `drawer.pointer.1` Given an open drawer, when the close part is clicked, then the drawer closes and the open change callback reports a close press reason. [base-ui, zag, reka]
- [ ] `drawer.pointer.2` Given a closed drawer, when the trigger is clicked, then the content and backdrop become visible and the open change callback reports a trigger press reason, and clicking the trigger again closes the drawer exactly once, in modal and non-modal mode alike. [zag, reka]
- [ ] `drawer.pointer.3` Given a pointerdown on the content or grabber whose button is not the primary one, when it fires, then no drag starts. [zag, corvu]
- [ ] `drawer.pointer.4` Given a pointerdown whose target or any ancestor up to the content root carries the no-drag opt-out attribute (`data-corvu-no-drag`, `data-no-drag` or `data-base-ui-swipe-ignore`), when a drag of 100px follows, then the drawer does not move at all and it is still open at its original height after release; base-ui's older `data-swipe-ignore` spelling no longer blocks the gesture. [base-ui, zag, corvu]
- [ ] `drawer.pointer.5` Given a pointerdown on a native `<input type="range">` or a slider thumb inside the drawer, when a drag follows, then no drag starts and the touchmove is not default-prevented, so the thumb moves instead of the drawer. [base-ui, corvu]
- [ ] `drawer.pointer.6` Given a non-empty text selection inside the content, when a drag of 100px starts there, then the gesture is released rather than dragging and the visible height is unchanged; base-ui also leaves a touch gesture alone when the selection's focus endpoint is inside the popup. [base-ui, zag, corvu]
- [ ] `drawer.pointer.7` Given a pointer down on the content, grabber or swipe area, when the movement along the drag axis stays inside the dead zone (0.3 pixels in corvu, 3 pixels on a zag swipe area) or the pointer is pressed and released in place after 200ms with no movement, then no drag begins and the drawer does not open or close. [base-ui, zag, corvu]
- [ ] `drawer.pointer.8` Given touch-emulated pointer events (pointerdown, pointermove, pointerup and pointercancel with `pointerType: "touch"`) carrying real displacement, when they are dispatched, then they are swallowed and never move, open or dismiss the drawer, because touch gestures are driven by touchstart, touchmove and touchend instead; corvu releases a touch drag only on touchend once `event.touches.length` is 0, so a multi-touch gesture does not release early. [base-ui, zag, corvu]
- [ ] `drawer.pointer.9` Given a drag in progress, when a touchstart or touchmove carrying two touches arrives, then the event is not default-prevented and no swipe state is set, so pinch zoom is left to the browser. [base-ui, corvu]
- [ ] `drawer.pointer.10` Given a drawer in its closing transition, or one kept mounted after close, when pointerdown fires, then no drag starts and the closed drawer cannot be grabbed back. [base-ui, corvu]
- [ ] `drawer.pointer.11` Given a drag that has begun on the content, when the pointer leaves the drawer and moves or releases over the document instead, then the drag keeps tracking and a pointerup that only reaches the document still ends it. [corvu, reka]
- [ ] `drawer.pointer.12` Given a drag in progress, when a contextmenu event fires, when a pointermove arrives with the secondary button held, or when the window loses focus, then the drag is released and the movement variables are cleared instead of the drawer staying stuck to the pointer. [base-ui, corvu, reka]
- [ ] `drawer.pointer.13` Given a drag in progress whose pointerup never arrives, when a pointermove with `buttons: 0` is delivered, then it is treated as the missing release: below the threshold the gesture cancels and the movement variable returns to `0px`, past the threshold it dismisses once, and the release move's own displacement is applied before the decision so a final jump across the threshold still dismisses. [base-ui, reka]
- [ ] `drawer.pointer.14` Given a gesture that latched a cancel state and never received a release, when a fresh press with a new pointer id repeats the drag past the threshold, then it dismisses once, and a threshold changed mid-gesture applies only from the next gesture because the active one snapshotted the old value. [base-ui, reka]
- [ ] `drawer.pointer.15` Given a drag that starts inside a scrollable descendant, when there is scroll remaining in the direction of travel, then the gesture is released to the scroller, the touchmove is not default-prevented and the drawer does not move, and when the scroller already sits at the edge in the dismiss direction (`scrollTop` 0 for a down drawer, the bottom edge for an up drawer, the left or right edge for a horizontal one) the touchmove is default-prevented, the swipe claims the gesture and a release past the threshold dismisses with a swipe reason. [base-ui, zag, corvu, reka]
- [ ] `drawer.pointer.16` Given a scroller on the axis across from the drawer's, when the first moves are ambiguous, then they are left to the browser, once the drawer axis passes the slop the gesture is claimed and every later move is default-prevented even when the finger comes back inside the slop, a non-cancelable touchmove before the claim yields the gesture for the rest of it, and a non-cancelable touchmove after the claim keeps driving the drag. [base-ui, reka]
- [ ] `drawer.pointer.17` Given content that overflows only on the axis across from the drawer's, when a drag runs along that cross axis, then the touchmove is not default-prevented and no swipe starts, so native scrolling is untouched. [base-ui, reka]
- [ ] `drawer.pointer.18` Given an open drawer, when a fast flick in the dismiss direction is released, then the drawer closes even though the distance alone would not: zag dismisses a 200px drag delivered in 100ms past its 700 px/s velocity threshold, and reka requires at least 0.2 px/ms of release velocity and adds `clamp(velocity, -4, 4) * 300` pixels of projected travel before choosing the target. [zag, reka]
- [ ] `drawer.pointer.19` Given a long slow drag that ends in a flick, when the pointer is released, then only the most recent motion decides the velocity, because base-ui measures the release over the last movement inside an 80ms window and corvu resets its velocity cache after 200ms. [base-ui, corvu]
- [ ] `drawer.pointer.20` Given a very short or very slow release, when the velocity is computed, then the elapsed duration is clamped to a floor (50ms in base-ui, so 30px in 5ms reads as 0.6 px/ms rather than 3) and a near-zero velocity is treated as no momentum at all (corvu coerces any value between -1 and 1 to exactly 1, reka returns no release scalar below 0.2 px/ms). [base-ui, corvu, reka]
- [ ] `drawer.pointer.21` Given a drag whose dominant axis is across the drawer's, when the absolute cross-axis delta stays above the drawer-axis delta, then the swipe direction never locks, the drawer neither opens nor dismisses, and a sustained unattributed drag still moves between snap points without closing. [base-ui, corvu]
- [ ] `drawer.pointer.22` Given a closed drawer with a swipe area, when a swipe in the opening direction runs across it with either touch events or mouse pointer events, then the content and the backdrop become visible and both the swipe area and the content carry the open state. [base-ui, zag]
- [ ] `drawer.pointer.23` Given a swipe area with no direction of its own, when its opening direction is resolved, then it is the opposite of the drawer's swipe direction, and a per-swipe-area direction prop overrides it. [base-ui, zag]
- [ ] `drawer.pointer.24` Given a disabled swipe area, when a swipe in the opening direction runs across it, then the drawer stays closed, and disabling the swipe area mid-gesture cancels the gesture, drops the swiping marker and adds the disabled marker. [base-ui, zag]
- [ ] `drawer.pointer.25` Given a cancelable non-touch pointerdown on the swipe area, when it fires, then `preventDefault()` is called on it, and a non-cancelable pointerdown is left alone with `defaultPrevented` false. [base-ui, zag]
- [ ] `drawer.pointer.26` Divergence: the dismiss distance threshold is a fraction of the popup's own size, with a swipe of 45 percent of the popup keeping the drawer open and one of 60 percent dismissing it. (decision needed) [base-ui]
- [ ] `drawer.pointer.27` Divergence: the dismiss distance threshold is `closeThreshold`, 0.25 of the content's visible height by default, so a 55 percent drag over 500ms closes the drawer and a 100px drag over 500ms leaves it open. (decision needed) [zag]
- [ ] `drawer.pointer.28` Divergence: the dismiss distance threshold is a fixed 40 pixels by default whatever the drawer's size, overridable per gesture, so a 60px drag dismisses and a 15px drag cancels. (decision needed) [base-ui, reka]
- [ ] `drawer.pointer.29` Divergence: dragging past the furthest snap point is resisted by square-root damping, so 150 pixels of overshoot moves the content about 12.2 pixels and the raw movement is returned as soon as the drag is back inside the open edge. (decision needed) [base-ui, reka]
- [ ] `drawer.pointer.30` Divergence: dragging past the furthest snap point is damped logarithmically as `6 * log(distance + 1)`, overridable by the author, giving rubber-band resistance rather than a clamp. (decision needed) [corvu]

- [ ] `drawer.pointer.32` Given an open drawer at a snap point, when a release covers 1 pixel in 19 milliseconds, then the drawer neither dismisses nor changes snap point, so a low-velocity twitch near a snap point is ignored. (candidate) [base-ui]
- [ ] `drawer.pointer.33` Given a drag that sweeps toward the open edge and then reverses back toward the closed edge just before release, when the pointer is released, then the drawer is not dismissed because the release velocity reversed direction. (candidate) [base-ui]
- [ ] `drawer.pointer.34` Given a drag that first pulls 50 pixels away from the dismiss direction and then reverses 70 pixels into it, when the pointer is released, then the drawer dismisses once, so the dismiss direction is adopted on reversal. (candidate) [reka]
- [ ] `drawer.pointer.35` Given a drag starting inside a scrollable descendant on Firefox, where the available scroll reads as 1 even when nothing can scroll, when the remaining scroll is measured, then a positive delta needs more than 1 pixel of remaining scroll to yield the gesture while a negative delta yields on any non-zero scroll offset. ### State

- [ ] `drawer.state.1` Given a drawer with no snap points configured, when it is used, then it has exactly two resting states, fully closed and fully open, from a default list of `[0, 1]` in corvu or `[1]` with a default snap point of 1 in zag. [zag, corvu]
- [ ] `drawer.state.2` Given a resolved snap point list, when the offsets are computed, then each entry's offset is the drawer's measured size minus that entry's height, the entries are ordered by ascending height, and a fully open entry has an offset of 0. [base-ui, zag, corvu, reka]
- [ ] `drawer.state.3` Given a released drag, when the target snap point is chosen, then it is the snap point nearest the velocity-projected offset, ties keep the earlier entry, and when the projection lands nearer the fully closed position than any snap point the drawer dismisses instead of snapping. [base-ui, corvu, reka]
- [ ] `drawer.state.4` Given sequential snap points, when a fast flick is released, then the drawer advances exactly one snap point in the drag direction, a slow drag that physically crosses the adjacent snap point still advances to it, a drag from the lowest snap point that ends mostly closed still dismisses, and a flick at the last point in the open direction stays there; corvu spells the same rule as `allowSkippingSnapPoints: false`, where the raw rather than the velocity-adjusted offset is searched. [base-ui, zag, corvu, reka]
- [ ] `drawer.state.5` Given a drag released onto the fully closed offset, when the release completes, then the drawer closes rather than writing that translate, so snapping to the closed position is the close, and a drag past the final sequential snap point unmounts the content. [base-ui, corvu, reka]
- [ ] `drawer.state.6` Given a drawer whose snap point is set programmatically, when the same value is set repeatedly or two values are set in the same tick, then only the last value applies, the change callback fires exactly once and never for a repeat of the current value. [base-ui, zag]
- [ ] `drawer.state.7` Given a drawer whose open state changes, when the change callback runs, then it receives the new state plus a reason naming the cause, one of a trigger press, a close press, a swipe or a close watcher. [base-ui, reka]
- [ ] `drawer.state.8` Given an open drawer, when its open percentage is read, then it is 1 minus the current offset over the content size and 0 while closed or unmeasured; zag clamps it to 0 through 1 while corvu lets it exceed 1 during damped overscroll, so anything driving a backdrop opacity from it must tolerate values above 1. [zag, corvu]
- [ ] `drawer.state.9` Given several drawers registered in one stack, when their open state, height and swipe progress are written, then the stack reports an open count, takes the frontmost height from the highest-order open drawer, clamps swipe progress to 0 through 1, batches every write in a tick into a single notification, skips notifying for an unchanged snapshot, and stops notifying after an unsubscribe. [base-ui, zag]
- [ ] `drawer.state.10` Given several triggers bound to one drawer, when a trigger other than the current one is clicked, then the drawer swaps its content rather than closing, the clicked trigger reports `aria-expanded="true"` with `aria-controls` matching the content id and the others report false. [base-ui, zag]
- [ ] `drawer.state.11` Divergence: a bare number snap point is a fraction of the drawer's own size, so 1 is fully open and 0 fully closed, and pixel values must be written as strings. (decision needed) [zag, corvu]
- [ ] `drawer.state.12` Divergence: a bare number snap point is a pixel height clamped to the measured popup height, so `200` resolves to a 200 pixel tall drawer, while a value at or below 1 is read as a fraction. (decision needed) [base-ui, reka]
- [ ] `drawer.state.13` Divergence: an unsupported snap point is dropped silently and the remaining points still resolve, covering `NaN`, non-numeric strings, percent strings, non-finite and negative values, with values above the popup height clamped to it, the last of duplicate heights kept, and `rem` resolved against the root font size. (decision needed) [base-ui, reka]
- [ ] `drawer.state.14` Divergence: a snap point that is not a number or a string ending in `px` throws at runtime with a message naming the offending value, so `rem`, `vh` and percent units are rejected rather than dropped. (decision needed) [corvu]
- [ ] `drawer.state.15` Given a drawer whose snap point list is empty or resolves to nothing usable, when a drag is released, then no snap point is active, the snap offset reads as `0px` and the drawer falls back to plain swipe dismissal. (candidate) [base-ui]
- [ ] `drawer.state.16` Given an open drawer at a non-default snap point, when it is closed by a close press, then the active snap point resets to the configured default snap point, or to the first point when no default is given, with the change reported under a close press reason, and a canceled close leaves the snap point where it was. (candidate) [base-ui]
- [ ] `drawer.state.17` Given a controlled drawer whose parent cancels the change, when a swipe close or a snap point change is attempted, then the previous snap point is restored, the content keeps its open state and the swipe movement variables return to `0px`; a parent that simply ignores the change restores the snap point in the same way, while a parent that accepts a swipe close resets to the default snap point rather than the pre-swipe one. (candidate) [base-ui]
- [ ] `drawer.state.18` Given a controlled drawer whose open prop is permanently true, when a swipe past the threshold is released, then the change callback still reports the dismiss intent while the content keeps its open state and its swipe styles are cleared. (candidate) [base-ui]
- [ ] `drawer.state.19` Given a snap point value that is not in the configured list, when it is set from context, then the active snap point does not change and the change callback still reports the attempted value with a reason of none. (candidate) [base-ui]
- [ ] `drawer.state.20` Given break points that override the midpoint between two snap points, when a drag is released, then the target is chosen by comparing against that break point rather than by nearest distance, so the drawer can be biased toward opening or closing; the list must be one shorter than the snap point list and accepts null entries to keep individual default midpoints. (candidate) [corvu]

### Dismissal and layering

- [ ] `drawer.dismissal.1` Given an open drawer whose enter animation has finished, when the page outside it is pressed with a mouse or a touch, then the content and the backdrop are both hidden, including for a drawer that was opened by a swipe. [base-ui, zag]
- [ ] `drawer.dismissal.2` Given a drag in progress that wanders outside the content, when the drag is released, then the drawer is not dismissed as an outside press, because outside-pointer dismissal is suppressed for the duration of the gesture. [base-ui, corvu]
- [ ] `drawer.dismissal.3` Given a drawer and its defaults, when no props are passed, then dismissal on outside interaction, dismissal on Escape, modal behavior and page scroll prevention are all on; corvu additionally defaults pinch zoom to blocked while the drawer is open, unlike its plain dialog. [zag, corvu]
- [ ] `drawer.dismissal.4` Given a non-modal drawer, when it is open, then the page behind stays interactive and the page scroll position is not locked or restored, while a modal drawer locks it. [base-ui, zag]
- [ ] `drawer.dismissal.5` Given a drawer opened by a swipe, when the click synthesized by the release lands on the page with no fresh pointerdown, then the drawer stays open whatever the pointer type (mouse, pen or touch), and the next real outside press dismisses it; a trusted click arriving with no preceding pointerdown is suppressed exactly once. (candidate) [base-ui]
- [ ] `drawer.dismissal.6` Given a drawer opened by a swipe with focus still outside it, when a pointerless virtual click arrives, such as Enter on an outside button or a screen reader activation, then the drawer dismisses. (candidate) [base-ui]
- [ ] `drawer.dismissal.7` Given a swipe-open gesture interrupted by the secondary mouse button or by a context menu, when a mouse outside press follows, then the drawer dismisses, so the interruption re-enables outside press dismissal. (candidate) [base-ui]
- [ ] `drawer.dismissal.8` Given an open drawer in a browser with `CloseWatcher`, when the watcher emits close twice, then the open change callback fires exactly once with false and a close watcher reason. (candidate) [base-ui]
- [ ] `drawer.dismissal.9` Given a modal drawer with the software keyboard open, when WebKit's native reveal scroll moves the window past the scroll lock, then the page is scrolled back to the top with `behavior: "instant"`, and a non-modal drawer is left alone. (candidate) (safari-only) [base-ui]
- [ ] `drawer.dismissal.10` Given a nested drawer open inside a parent drawer, when a tap lands on a keyboard input in the parent, then the parent's own touch-to-focus handling stands down and the native tap is preserved. (candidate) (browser-only) [base-ui]

### Positioning

- [ ] `drawer.positioning.1` Given an open drawer at a resolved snap point, when its inline style is read, then the snap offset is published as a custom property equal to the measured size minus the snap height, negative for upward drawers, `0px` when no snap point is active, and the content is marked as expanded when the offset is zero. [base-ui, zag, reka]
- [ ] `drawer.positioning.2` Given a drawer opened at a configured default snap point, when it settles, then the content rests at that snap height, with `rem` values measured against the root font size and fractions against the measured size, so 0.5 of an 800 pixel drawer rests at a 400 pixel offset and a 20rem snap point lands within 4 pixels of 20rem. [zag, reka]
- [ ] `drawer.positioning.3` Given an open drawer at an intermediate snap point, when the grabber is dragged toward the open edge and then back, then the visible height grows while dragging out and returns to within 4 pixels of the original snap height. (candidate) [zag]
- [ ] `drawer.positioning.4` Given a drawer whose popup reports a height of 0, when a drag is released, then no snap point resolves and the drawer does not dismiss, because snap points are measured against the popup's real size. (candidate) [base-ui]
- [ ] `drawer.positioning.5` Given a drawer with the virtual keyboard provider, when a field is focused and the visual viewport shrinks, then bottom padding and scroll padding are added to the nearest scrollable ancestor, its overflow anchor is set to none, and the field's vertical center is scrolled to the center of the band between the scroller's top and the shrunken viewport; blurring the field, closing the drawer or moving focus to another scroller restores the previous padding, scroll padding and overflow anchor. (candidate) (browser-only) [base-ui]
- [ ] `drawer.positioning.6` Given the same provider, when the focused field has no scrollable ancestor, then the slack is skipped and the viewport instead publishes a keyboard inset of `window.innerHeight - min(innerHeight, visualViewport.offsetTop + height)`, returning to `0px` on blur; slack always goes on the scroll ancestor and never on an overflowing textarea, whose own scrolling cannot lift it above the keyboard. (candidate) (browser-only) [base-ui]
- [ ] `drawer.positioning.7` Given the same provider, when the visual viewport shrinks by less than the 60 pixel keyboard threshold, when it is pinch-zoomed, when `visualViewport` is unavailable, or when the provider is not present, then no padding, scroll padding or keyboard inset is applied. (candidate) (browser-only) [base-ui]
- [ ] `drawer.positioning.8` Given a field inside an open shadow root within the drawer, when it is focused and the viewport shrinks, then the capture-phase focusin listener retargets through the shadow boundary and the light-DOM scroller gets the same slack and keyboard inset. (candidate) (browser-only) [base-ui]
- [ ] `drawer.positioning.9` Given a focused field whose surrounding geometry is still moving, when the alignment scroll is scheduled, then it waits for the destination to stop moving, commits once after a bounded number of frames when the geometry never settles, re-issues itself when a scroll stalls (WebKit canceling a smooth scroll), uses an instant scroll under `prefers-reduced-motion` without restarting a progressing or settled one, and is abandoned entirely once the user presses on the scroller. (candidate) (browser-only) [base-ui]

### Animation and presence

- [ ] `drawer.animation.1` Given a drawer whose content has a CSS transition or Web Animation, when it opens, closes or snaps, then the transition drives the change and teardown waits for a transitionend on the content element itself, so a transition on a descendant cannot end it early. [zag, corvu]
- [ ] `drawer.animation.2` Given a drag in progress, when the content's inline style is read, then its transition is suppressed (`transition-duration: 0ms` or `transition: none`) so it follows the finger with no easing, and the override is removed on release so the author's transition animates the snap. [base-ui, zag, corvu]
- [ ] `drawer.animation.3` Given a drawer that opens at a non-default snap point, when the open effect runs, then the snap target is applied after the first paint, and the offset is written again on every mount, so a reopened drawer animates from the closed position to the right snap point instead of jumping or resting at `0px`. [corvu, reka]
- [ ] `drawer.animation.4` Given a swipe that dismisses, when the pointer is released, then the movement variables keep their released values so the close animation starts from the drag position, and a swipe that cancels resets them to `0px` so the drawer animates back to rest. [base-ui, reka]
- [ ] `drawer.animation.5` Given a release that lands on a different snap point, when the release is handled, then the new snap offset is written and the movement variable cleared in the same synchronous step, so the transform never reverts to the old snap for a frame. [base-ui, reka]
- [ ] `drawer.animation.6` Given a provider with an indent, when a drag is in flight, then the indent's swipe progress rises above 0, its frontmost height reads the open drawer's measured height and its computed transform differs from the resting one, and after release and settle the progress returns to 0 with the height cleared. [base-ui, zag]
- [ ] `drawer.animation.7` Given a drawer with no transition defined, so the computed transition duration is 0, when it opens or closes, then the transition state clears immediately and the close path runs directly instead of waiting for a transitionend that never arrives. (candidate) [corvu]
- [ ] `drawer.animation.8` Given resize transitions enabled, when the content's size changes on the drawer's own axis, then the drawer enters a resizing transition with the measured pixel height (for top and bottom) or width (for left and right) pinned inline for its duration, because a percentage cannot be transitioned, and a transitionend does not clear that state. (candidate) [corvu]
- [ ] `drawer.animation.9` Given a parent drawer whose height follows its frontmost nested drawer, when a nested drawer starts closing, then the parent drops the nested count to 0 and loses the nested-open marker while the child is still animating out, keeps a fixed height through that exit animation, and restores the fixed height before reapplying the nested marker when the child is reopened. (candidate) (browser-only) [base-ui]

- [ ] `drawer.a11y.1` Given a drawer closed and then open, when axe runs over the document body, then there are no violations; zag runs the same check scoped to the content part with the color contrast and scrollable region focusable rules disabled. [zag, reka]

### Notes and edge cases

- [ ] `drawer.notes.1` Given no layout and no `ResizeObserver`, when the drawer measures itself, then every snap point resolves to an offset of 0 and the open percentage collapses to 0, so a conformance run must stub element sizes, `ResizeObserver` and the scroll metrics (`scrollHeight`, `clientHeight`, `scrollTop`) with real numbers before any snap or drag assertion means anything. [corvu, reka]
- [ ] `drawer.notes.2` Given a drag that has begun, when a test drives it, then the move and release events must be dispatched on the document rather than on the content, because only pointerdown, touchstart and transitionend are bound to the element, and both the pointer and the touch event streams must be exercised because the implementations handle them separately. [base-ui, corvu, reka]
- [ ] `drawer.notes.3` Given the whole drawer surface, when its coverage is assessed, then it is the least independently verified component here: corvu ships no test file, vitest config or Playwright setup at all, and Ark UI has no drawer test in any framework package, leaving the zag end-to-end specs and one stack unit test. [ark, corvu]
- [ ] `drawer.notes.4` Given a drawer whose content has no title part, when it opens, then a development warning is logged. (candidate) [reka]
- [ ] `drawer.notes.5` Given a popup rendered without the wrapper that owns swipe handling, when it mounts in development, then a warning says swipe handling and touch scroll locking are disabled and names the wrapper to add. (candidate) [base-ui]
- [ ] `drawer.notes.6` Given a computed transition duration that reads as an empty string outside a real engine, when the zero-duration short circuit is evaluated, then `parseFloat("")` is `NaN` rather than 0 and the drawer never finishes opening or closing, so the check has to be written NaN-safe. (candidate) [corvu]
- [ ] `drawer.notes.7` Given an active swipe, when the popup is removed by props or the whole tree unmounts, then the swiping markers and the provider and backdrop swipe state are cleared, further moves do nothing and no close is reported. (candidate) [base-ui]
- [ ] `drawer.notes.8` Given a drag session on the content or grabber, when it is committed, then it only starts while the drawer is open and not closing, and a pointer event counts as inside the drawer when its target is contained by either the content or the swipe area subtree. (candidate) [zag]

## Deferred

- No APG or WHATWG HTML material covers the drawer pattern, so this file has no normative bullet. The dialog-level rules it inherits (modal semantics, focus trap, Escape) should be pulled from the dialog spec rather than restated here.
- No Forms subsection. Nothing in the research ties a drawer to form submission, validation or a form owner; the input-heavy bullets are about the software keyboard and live under Pointer, Focus management and Positioning.
- Library-internal assertions dropped: `describeConformance` suites (prop and ref forwarding, `render` prop support, class merging), missing-context error message text, exported api symbol lists, default id naming schemes, corvu's `data-corvu-*` marker swapping, `createWritableMemo` and memoized-root internals, zag's `replaces` send semantics, base-ui's layout-versus-passive-effect ordering probes and profiler re-render counts, stack registry notification plumbing, and the pure helper unit tests for `getSnapPointSwipeMovement`, `closestSnapPointIndex`, `getDisplacement` and `computeSwipeReleaseScalar` (their rules are stated once as behavior instead).
- Unresolved beyond the four divergence pairs: the exit transition duration curve is specified only by reka (velocity and remaining distance scaled into a 80ms to 360ms window, scalar 0.1 to 1), so it is recorded in the animation bullets without a cross-library number to check it against.
- Unresolved: whether the open percentage clamps to 0 through 1 (zag) or may exceed 1 during damped overscroll (corvu). Folded into one bullet rather than split, because the underlying formula agrees.
- Not covered by any source: the ordering of Escape and outside press across nested drawer layers (which layer consumes the event first), and whether a nested drawer's Escape closes only the frontmost layer. base-ui only establishes that dialogs nested inside a drawer are not counted as drawers.
- Not covered by any source: scroll lock behavior for the drawer itself beyond zag's `preventScroll` default and base-ui's WebKit reveal-scroll restore. No source tests the iOS rubber-band or `position: fixed` body technique directly.
