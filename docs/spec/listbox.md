# listbox

Covers `role="listbox"` and `role="option"`: the standalone listbox, the
collapsible button-plus-listbox variant, single and multiple selection. The
listbox popup owned by a `select` or `combobox` trigger is specified in
`select.md` and `combobox.md`; only the parts that belong to the listbox itself
live here.

## listbox

### Roles and attributes

- [ ] `listbox.roles-and-attributes.1` Given an element that contains or owns all the options, then it has `role="listbox"`. [apg]
- [ ] `listbox.roles-and-attributes.2` Given each option, then it has `role="option"` and is contained in or owned by either the `listbox` element or a `role="group"` inside the listbox; a missing required parent is a critical failure. [apg, axe, react-aria, kobalte, zag, ark, reka]
- [ ] `listbox.roles-and-attributes.3` Given `role="listbox"`, then it owns at least one `group` or `option`; direct children with any other role fail "Element has children which are not allowed", so intervening `li` or wrapper elements carry `role="presentation"`. An empty listbox is reported incomplete rather than failing, because `listbox` is in axe's `reviewEmpty` list. [apg, axe]
- [ ] `listbox.roles-and-attributes.4` Given a listbox with grouped options, then every group contains at least one option and has an accessible name from `aria-label` or `aria-labelledby`. [apg, axe, react-aria, zag]
- [ ] `listbox.roles-and-attributes.5` Given a listbox that is not part of another widget such as a combobox, then it has either a visible label referenced by `aria-labelledby` or a value for `aria-label`; visible text content is not accepted as a name source, at serious impact. [apg, axe, react-aria, kobalte, zag, reka]
- [ ] `listbox.roles-and-attributes.6` Given a listbox that allows more than one option to be selected, then it has `aria-multiselectable="true"`; otherwise the attribute is `"false"` or its default false is implied. [apg, react-aria, kobalte, zag, ark]
- [ ] `listbox.roles-and-attributes.7` Given a listbox, then selection state is expressed with either `aria-selected` or `aria-checked` on the options, never both; if `aria-selected` is used then `aria-checked` is not specified on any option, and vice versa. [apg]
- [ ] `listbox.roles-and-attributes.8` Given a listbox that uses both `aria-selected` and `aria-checked`, then the two states differ in meaning, the interface makes each meaning apparent, and a separate control exists for each; the APG strongly recommends avoiding such a design. [apg]
- [ ] `listbox.roles-and-attributes.9` Given a design-system convention choice, then `aria-selected` for single-select and `aria-checked` for multi-select is the recommended convention, applied consistently across a site or app. [apg]
- [ ] `listbox.roles-and-attributes.10` Given a listbox without `aria-multiselectable="true"`, then no more than one option is selected at a time. [apg, react-aria, kobalte]
- [ ] `listbox.roles-and-attributes.11` Given a multi-select listbox, then every option carries an explicit `aria-selected="false"` from the start, not an absent attribute, so a test can tell "unselected" from "not selectable". [apg, react-aria, kobalte, zag, ark, reka]
- [ ] `listbox.roles-and-attributes.12` Divergence: given a single-select listbox using `aria-selected`, then unselected options have the attribute absent rather than `"false"`, and the previously selected option has it removed rather than set to `"false"`. [apg, react-aria] (decision needed)
- [ ] `listbox.roles-and-attributes.13` Divergence: given a single-select listbox, then every unselected enabled option carries an explicit `aria-selected="false"` (and, in kobalte, `aria-disabled="false"` as well). [kobalte, zag, ark, reka] (decision needed)
- [ ] `listbox.roles-and-attributes.14` Given a listbox whose full option set is not in the DOM because of virtualization or dynamic loading, then each rendered option carries `aria-setsize` and `aria-posinset`; the set size is the full collection size, not the rendered window. [apg, react-aria, reka]
- [ ] `listbox.roles-and-attributes.15` Given options arranged horizontally, then the listbox has `aria-orientation="horizontal"`; the default for `listbox` is `vertical`. [apg, react-aria, zag, reka]
- [ ] `listbox.roles-and-attributes.16` Given a standalone listbox, then the `listbox` element carries `tabindex="0"` and the options are not individual tab stops, with the active option named by `aria-activedescendant` on the container. [apg, zag]
- [ ] `listbox.roles-and-attributes.17` Given a listbox that is the popup of a collapsible button, then the `listbox` carries `tabindex="-1"` and receives focus programmatically when the button opens it. [apg]
- [ ] `listbox.roles-and-attributes.18` Given a decorative checkmark or indicator glyph inside an option, then it carries `aria-hidden="true"` and is not focusable and carries no global ARIA attribute. [apg, axe, zag]
- [ ] `listbox.roles-and-attributes.19` Given a `role="option"` element, then all of its descendants are forced presentational, so it contains no focusable widget-role descendant; a list of interactive elements uses the grid pattern instead. [apg, axe]
- [ ] `listbox.roles-and-attributes.20` Given the trigger button of a collapsible listbox, then it has `aria-haspopup="listbox"`, a resolvable `aria-labelledby`, and `aria-expanded="true"` while open; the APG example removes `aria-expanded` entirely rather than setting it to `"false"` when closed. [apg]
- [ ] `listbox.roles-and-attributes.24` Given `role="option"`, then it has an accessible name from visible text, `aria-label`, `aria-labelledby` or `title`, at serious impact. [axe, react-aria, kobalte]
- [ ] `listbox.roles-and-attributes.37` Given a listbox rendered as a native `select`, then it has an accessible name from an implicit or explicit `label`, `aria-label`, `aria-labelledby`, `title` or a presentational role, and the explicit label is not hidden, at critical impact. [axe]
- [ ] `listbox.roles-and-attributes.38` Given `role="listbox"` in the axe role table, then it is a widget-type role whose role-specific allowed attributes are `aria-multiselectable`, `aria-readonly`, `aria-required`, `aria-activedescendant`, `aria-expanded` and `aria-orientation`, its superclass is `select`, and a name is required. [axe]
- [ ] `listbox.roles-and-attributes.39` Given `role="option"` in the axe role table, then its role-specific allowed attributes are `aria-selected`, `aria-checked`, `aria-posinset` and `aria-setsize`; `aria-selected` is allowed rather than required because it is implicit, its superclass is `input`, its name may come from content, and its children are presentational. [axe]
- [ ] `listbox.roles-and-attributes.21` Given a disabled option, then it carries `aria-disabled="true"` plus a `data-disabled` marker, and its enabled siblings carry neither. [react-aria, kobalte, zag, ark, reka]
- [ ] `listbox.roles-and-attributes.22` Given an option with an explicit `aria-label`, then the option has that label and has neither `aria-labelledby` nor `aria-describedby`, so an explicit label suppresses the derived associations entirely. [react-aria, kobalte]
- [ ] `listbox.roles-and-attributes.23` Given an option built from a label part and a description part, then its `aria-labelledby` points at the label element and its `aria-describedby` at the description element. [react-aria, kobalte]
- [ ] `listbox.roles-and-attributes.25` Given a group heading rendered inside the listbox, then the heading element carries `role="presentation"` and the `role="group"` element's `aria-labelledby` points at it; a group named only by `aria-label` keeps that instead. [react-aria, zag]
- [ ] `listbox.roles-and-attributes.27` Given each option, then it exposes its own value in the DOM as a stable identity attribute (`data-key` in kobalte, `data-value` in zag) so a test can address an option without relying on its text. [kobalte, zag]
- [ ] `listbox.roles-and-attributes.28` Given an option, then highlight and selection are separate attributes: `data-highlighted` for the active option and `data-state="checked"`/`"unchecked"` (or `data-selected`) for selection. [zag, ark, reka, react-aria]
- [ ] `listbox.roles-and-attributes.29` Given a listbox with an empty collection, then the container is marked empty (`data-empty`) and, where an empty-state renderer is supplied, a single option carries its content. [react-aria, zag]
- [ ] `listbox.roles-and-attributes.30` Given an item indicator part, then it is absent from the DOM unless its option is selected, and a force-mount flag renders it for every option. [kobalte, zag]
- [ ] `listbox.roles-and-attributes.26` Given a sectioned listbox, then `aria-posinset` numbers options continuously across section boundaries (1..n over the whole collection) and `aria-setsize` is the whole collection size. [react-aria] (candidate)
- [ ] `listbox.roles-and-attributes.31` Given the content element of a listbox, then `aria-activedescendant` and a mirrored `data-activedescendant` both name the highlighted option's id. (candidate) [zag]
- [ ] `listbox.roles-and-attributes.32` Given a grid-layout listbox, then the container and items carry `data-layout="grid"` (versus `"list"`) and the container sets a `--column-count` custom property, so CSS can tell the two apart. (candidate) [zag]
- [ ] `listbox.roles-and-attributes.33` Given a listbox separator, then it carries `role="presentation"` and `data-orientation` but no `aria-orientation`, unlike a standalone separator; the same holds for the autocomplete, combobox and select separators. (candidate) [base-ui]
- [ ] `listbox.roles-and-attributes.34` Given a collapsible listbox trigger, then `type="button"` is set by default, is not overwritten when a `type` is already present, is set when the polymorphic `as` resolves to a button, and is omitted when it resolves to a non-button. (candidate) [headlessui]
- [ ] `listbox.roles-and-attributes.35` Given a trigger and a label part, then the two are linked through `aria-labelledby` on the trigger. (candidate) [headlessui]
- [ ] `listbox.roles-and-attributes.36` Given any listbox part rendered without its root ancestor, then it throws on mount. (candidate) [headlessui]

### Keyboard

- [ ] `listbox.keyboard.1` Given a single-select listbox receiving focus with no option selected, then focus is set on the first option, and that option may be automatically selected. [apg, kobalte, reka, zag]
- [ ] `listbox.keyboard.2` Given a single-select listbox receiving focus with an option already selected, then focus is set on that selected option. [apg, react-aria, kobalte]
- [ ] `listbox.keyboard.3` Given a multi-select listbox receiving focus with no option selected, then focus is set on the first option and no selection state changes. [apg]
- [ ] `listbox.keyboard.4` Given a multi-select listbox receiving focus with one or more options selected, then focus is set on the first selected option in the list. [apg, react-aria]
- [ ] `listbox.keyboard.5` Given focus in a vertical listbox, when Down Arrow is pressed, then focus moves to the next option and `aria-activedescendant` advances one option; in a single-select listbox selection may move with focus. [apg, react-aria, kobalte, zag, ark, reka, corvu]
- [ ] `listbox.keyboard.6` Given focus in a vertical listbox, when Up Arrow is pressed, then focus moves to the previous option; in a single-select listbox selection may move with focus. [apg, react-aria, kobalte, zag, reka, corvu]
- [ ] `listbox.keyboard.7` Given a standalone single-select listbox at its last option, when Down Arrow is pressed repeatedly, then focus clamps at the last option and does not wrap; Up Arrow at the first option clamps likewise. A standalone listbox clamps where a combobox popup wraps. [apg]
- [ ] `listbox.keyboard.8` Given a listbox with nothing yet active, when an arrow key is pressed, then focus lands on the first option and no further movement happens on that press. [apg, zag]
- [ ] `listbox.keyboard.9` Given a grouped listbox, when Down Arrow is pressed on the last option of a group, then focus moves to the first option of the next group, and Up Arrow on a group's first option moves to the last option of the previous group: arrow navigation is one flat sequence across group boundaries. [apg, react-aria]
- [ ] `listbox.keyboard.10` Given focus in a listbox, when Home is pressed, then focus may move to the first option and End to the last, with selection following in a single-select listbox; supporting both is strongly recommended for lists of more than five options. [apg, react-aria, kobalte, zag, corvu]
- [ ] `listbox.keyboard.11` Given a listbox, when End is pressed twice, then focus lands on the last option and stays there; Home twice lands on the first and stays. [apg, zag]
- [ ] `listbox.keyboard.12` Given options arranged horizontally, then Down Arrow behaves as Right Arrow and vice versa, and Up Arrow as Left Arrow and vice versa. [apg, react-aria, reka, zag]
- [ ] `listbox.keyboard.13` Given a listbox, then typeahead is supported for all listboxes and especially those with more than seven options: a single character moves focus to the next item whose name starts with it, and several characters typed in rapid succession move focus to the next item starting with the whole string. [apg, react-aria, kobalte, zag, reka, headlessui, bits]
- [ ] `listbox.keyboard.14` Given a listbox typeahead, then matching is a case-insensitive prefix match against the option's text. [apg, react-aria, kobalte, reka, headlessui, bits]
- [ ] `listbox.keyboard.15` Given a listbox typeahead, then the search begins at the option after the currently active one and, finding no match, wraps and searches from the first option up to the active one. [apg, react-aria, reka, bits]
- [ ] `listbox.keyboard.16` Given a listbox typeahead, then the accumulated search string resets after a period of inactivity, after which the next keystroke starts a fresh search. [apg, react-aria, kobalte, reka, headlessui]
- [ ] `listbox.keyboard.65` Divergence: the typeahead reset interval is 500 ms. [apg] (decision needed)
- [ ] `listbox.keyboard.66` Divergence: the typeahead reset interval is 1000 ms. [reka] (decision needed)
- [ ] `listbox.keyboard.17` Divergence: given a listbox typeahead whose buffer has just timed out, when the same single character is typed again, then focus advances to the next option starting with that character, because the search always resumes after the current position. [apg] (decision needed)
- [ ] `listbox.keyboard.18` Divergence: given a listbox typeahead whose buffer has just timed out, when the same single character is typed again, then focus stays on the current match rather than advancing, because the buffer resets to a fresh single-character search. [react-aria, kobalte] (decision needed)
- [ ] `listbox.keyboard.19` Given a listbox typeahead, when two characters are typed quickly, then only options whose name starts with both match: typing "c" then "a" skips an option starting with "c" that is not "ca". [apg, react-aria, headlessui, reka, bits]
- [ ] `listbox.keyboard.30` Given a multi-select listbox, then one of two selection models is implemented: the recommended model, needing no modifier while navigating, or the alternative model, in which moving focus without Shift or Control unselects everything except the focused option. [apg]
- [ ] `listbox.keyboard.31` Given the recommended multi-select model, when Space is pressed, then the focused option's selection state toggles between `"true"` and `"false"`. [apg, react-aria, kobalte, zag, reka]
- [ ] `listbox.keyboard.32` Given a single-select listbox, when Space is pressed, then nothing toggles, because the APG implementation guards the toggle on `aria-multiselectable`. [apg]
- [ ] `listbox.keyboard.33` Given a multi-select listbox, when a plain arrow key or Home or End moves focus, then `aria-activedescendant` moves but the newly focused option stays `aria-selected="false"` and nothing becomes selected. [apg]
- [ ] `listbox.keyboard.34` Given a multi-select listbox, when the bare Shift key is pressed, then the range anchor is captured as the index of the currently active option. [apg, zag]
- [ ] `listbox.keyboard.35` Given a multi-select listbox with the anchor at option 0, when Shift+Down Arrow is pressed, then options 0 and 1 are both selected and everything else is unselected; each further press extends the range one option. [apg, react-aria, reka]
- [ ] `listbox.keyboard.36` Given a multi-select listbox, when a plain click sets a new anchor and Shift+Down Arrow is then pressed, then the previous selection is overwritten, not extended: every option inside the range gets `"true"` and every option outside it `"false"`. [apg]
- [ ] `listbox.keyboard.37` Given a multi-select listbox, when Shift+Down Arrow is pressed past the last option or Shift+Up Arrow past the first, then the range clamps at that end without wrapping or erroring. [apg, corvu]
- [ ] `listbox.keyboard.39` Given a multi-select listbox with the last option selected, when Control+Shift+Home is pressed, then every option from the first to the focused one is selected; with the first selected, Control+Shift+End selects every option from the focused one to the last. In react-aria these extend rather than replace the existing selection. [apg, react-aria]
- [ ] `listbox.keyboard.40` Given a multi-select listbox, when Shift+Home or Shift+End is pressed without Control, then the selection does not change: the Control modifier is required for the range-to-end shortcuts. [apg]
- [ ] `listbox.keyboard.41` Given a multi-select listbox, when Control+A (Command+A on macOS) is pressed, then all options become selected, and if all are already selected it may unselect them all; react-aria reports the selection as the string `all`. [apg, react-aria, zag]
- [ ] `listbox.keyboard.42` Given a single-select listbox, when Control+A is pressed, then it is a no-op: focus does not move and no option gains selection; zag throws from `selectAll()` when the mode is not multiple. [apg, react-aria, zag]
- [ ] `listbox.keyboard.43` Given a multi-select listbox, when a plain letter is typed without Control, then it performs typeahead and selects nothing. [apg]
- [ ] `listbox.keyboard.44` Given the alternative multi-select model, when Control+Down Arrow or Control+Up Arrow is pressed, then focus moves without changing any selection state, and Control+Space changes the focused option's selection state. [apg, react-aria]
- [ ] `listbox.keyboard.47` Given a multi-select listbox where selecting or unselecting everything matters, then separate "Select All" and "Unselect All" controls are provided, because that significantly improves accessibility. [apg]
- [ ] `listbox.keyboard.54` Given a collapsible listbox in the closed state, when Enter, Down Arrow or Up Arrow is pressed on the button, then the listbox opens, DOM focus moves onto the `listbox` element, and the first option becomes active; Up Arrow opens with the last option active in headlessui. [apg, headlessui]
- [ ] `listbox.keyboard.55` Given a collapsible listbox opened with a value already selected, then the selected option is the active one rather than the first. [apg, headlessui]
- [ ] `listbox.keyboard.56` Given an open collapsible listbox, when Enter or Space is pressed with an active option, then the listbox closes and that option is chosen and shown on the button; with no active option it just closes. [apg, headlessui]
- [ ] `listbox.keyboard.57` Given an open collapsible listbox, when Escape is pressed, then the listbox closes, focus returns to the button, and the current selection is kept rather than reverted. [apg, headlessui]
- [ ] `listbox.keyboard.62` Given any recognized navigation key, then `preventDefault` is called before the active item changes, and with an empty item list no key is handled and nothing is prevented. [apg, corvu, zag]
- [ ] `listbox.keyboard.64` Given a reorderable listbox, then Page Up and Page Down, or Alt+Up Arrow and Alt+Down Arrow, may move the focused option within the list, and Enter or Delete may move selected options to a sibling list, each gated on the corresponding button's `aria-keyshortcuts`. [apg]
- [ ] `listbox.keyboard.20` Given a listbox typeahead, then a space character is part of the search string rather than a selection key: typing "f","o","o"," " moves from "Foo" to "Foo Bar", and continuing "b","a","z" reaches "Foo Baz". [react-aria, headlessui, bits]
- [ ] `listbox.keyboard.21` Given a single-select listbox where a typeahead search is in flight, when Space is pressed, then it extends the search and selects nothing; once the search has timed out, Space selects the focused option and fires one selection change. [react-aria, zag]

### Pointer

- [ ] `listbox.pointer.1` Given a listbox, when an option is clicked, then it becomes the active option, its selection is toggled in a multi-select listbox or set in a single-select one, and it is scrolled into view. [apg, react-aria, kobalte, zag, ark, reka, headlessui]
- [ ] `listbox.pointer.2` Given a click on something that is not a `role="option"` element, then it is ignored. [apg]
- [ ] `listbox.pointer.4` Given a multi-select listbox, when an option is Shift+clicked, then every option from the range anchor to the clicked option becomes selected and everything outside that range unselected, and the native text-selection default is suppressed on `mousedown`. [apg, react-aria]
- [ ] `listbox.pointer.3` Given a disabled option, when it is clicked, then no selection change fires and the existing selection is untouched. [react-aria, kobalte, zag, headlessui]
- [ ] `listbox.pointer.5` Given a single-select listbox with empty selection allowed, when the selected option is clicked, then it becomes unselected and the change fires with an empty selection. [kobalte, react-aria, reka]
- [ ] `listbox.pointer.6` Given a multi-select listbox, when an already selected option is clicked, then it is deselected and the change payload is the remaining selection. [react-aria, kobalte, reka]
- [ ] `listbox.pointer.9` Given an option under the pointer, then hover marks it active or highlighted only when the component opts in (`highlightOnHover` per item in zag, on the root in reka, always in headlessui); moving over an already highlighted or a disabled option is a no-op and emits nothing. [zag, reka, headlessui, react-aria]
- [ ] `listbox.pointer.10` Given a hover-highlighting listbox, then the highlight is driven from the hovered element itself without querying the collection, and leaving an option makes it inactive again. [reka, headlessui]
- [ ] `listbox.pointer.11` Given hover highlighting, then it applies only to a real mouse: the pointer type must be `mouse` and the current interaction modality `pointer`. [zag, react-aria]
- [ ] `listbox.pointer.13` Given an option click, then download-modifier clicks, new-tab clicks and contextmenu events are ignored, and a right click neither opens a collapsible listbox nor selects an option. [zag, headlessui]
- [ ] `listbox.pointer.17` Given a replace-mode listbox, when the already selected option is pressed again without a modifier, then it is not deselected and the change does not fire again; with the platform modifier held it toggles off. [react-aria, reka]
- [ ] `listbox.pointer.18` Given a replace-mode listbox, when a second option is clicked, then the selection moves to it and focus follows. [react-aria, reka]

- [ ] `listbox.notes-and-edge-cases.1` Given a list of interactive elements such as links, buttons or checkboxes, then a listbox is not used, because `option` forces its descendants presentational and the interaction model does not support interacting with elements inside an option; the grid pattern is used instead. ## Deferred

- Virtualized listboxes. react-aria and reka both have working virtualizer suites (rendered window size, `aria-setsize` over the full collection, `scrollToIndex` on the pre-selected row, surviving rows re-rendering when a filter shrinks the collection, loader rows positioned past the last item), and reka's need `getBoundingClientRect`, `scrollTo` and `ResizeObserver` stubs before any row renders. Both are out of scope until the suite has a virtualization harness; the `aria-setsize`/`aria-posinset` and empty-state bullets above are the parts that hold without one. [react-aria, reka]
- Drag and drop between and within listboxes: drop indicators with "Insert before/between/after" labels, `data-drop-target`, keyboard drags started with Enter or Alt+Enter, reordering, dropping on an option versus on the root, and dropping into an empty listbox. Only react-aria covers it. [react-aria]
- Grid-layout listboxes: two-dimensional arrow navigation, `data-layout="grid"`, `--column-count`, and the row-wise range helpers. react-aria mocks `getBoundingClientRect` for the whole grid and zag derives the layout from the collection; both need a layout harness. [react-aria, zag]
- Load-more and async collections driven by an IntersectionObserver sentinel. The listbox side is bullets 6 and 7 in Notes; the data-loading contract itself belongs with `combobox.md`'s async-list work. [react-aria]
- Reorderable listboxes (Alt+Arrow or Page Up/Down moving an option, Enter or Delete moving options to a sibling list, live-region announcements). APG has an example and react-aria covers the keyboard drag equivalent; no other library ships it. [apg, react-aria]
- The alternative APG multi-select model (moving focus without a modifier unselects everything except the focused option). No library implements it; we specify the recommended model and keep this as an option. [apg]
